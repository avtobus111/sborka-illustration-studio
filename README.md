# Сборка — векторная студия

Тестовое задание: заголовок или метафора → подбор существующих предметов → автоматическая композиция → редактирование → SVG.

## Запуск

Требуется **Node.js 20+** (проверено на Node.js 22). В Windows откройте **START.cmd**. При первом запуске он установит зависимости через npm, проверит/скачает открытую модель и откроет http://127.0.0.1:4173. Установка требует интернета; после подготовки модель работает локально, без внешнего AI API и без ключа. Если веса уже включены в ZIP, повторного скачивания не будет.

Другой способ:

```sh
npm ci
npm run setup:model
npm run build
npm start
```

Модель и токенизатор занимают примерно 135 МБ. В Git и архив исходников они не включены: setup скачивает файлы из зафиксированной ревизии Hugging Face и проверяет SHA-256. Файл assets/model-manifest.json содержит размеры и контрольные суммы. При ошибке модель не подменяется словарём: интерфейс сообщает проблему, явный выбор предметов остаётся доступным.

При запуске через START.cmd сервер работает в фоне. Лог: studio.log. Остановка сервера, запущенного вручную через npm start: Ctrl+C. Повторный START.cmd использует существующую студию. Отдельный dist/index.html позволяет работать по объектам, но для смыслового режима всё равно нужен запущенный локальный сервер.

## Демонстрация

Непрерывная запись работы студии: [demo/walkthrough.mp4](demo/walkthrough.mp4), **90 секунд**, H.264, без звука, только отдельное окно. Показаны смысловой запрос, варианты, палитра, S/L, формат, явные предметы и экспорт. Запись не смонтирована из отдельных кадров. Figma проверена отдельно на примере examples/02-savings.svg; это не файл из последнего шага записи. Протокол: demo/walkthrough-notes.md; снимок: demo/figma-import-proof.png.

Дополнительный краткий видеопоказ: [demo/demo.mp4](demo/demo.mp4), 35 секунд. Первые два шага — снимки настоящего интерфейса со сборкой, вариантами и ручным поворотом; затем три реальных результата модели и SVG-движка. Это пошаговый показ, не непрерывная запись экрана. Видео можно пересобрать скриптом scripts/render-demo.mjs при установленном FFmpeg.

Сценарий самостоятельной проверки в приложении:

1. Ввести **Найти общий язык** и нажать «Собрать»: телефон и пазлы.
2. Ввести **Копить на мечту**: кошелёк и монета.
3. Переключить формат, цветовую схему, S/L; выбрать объект, изменить его состояние и поворот, порядок слоёв.
4. В режиме «По объектам» ввести **книга, телефон, пазлы**, собрать композицию.
5. Скачать SVG. Исходные пути остаются векторными и сгруппированы по предметам. Пример examples/02-savings.svg импортирован в отдельный файл Figma; кошелёк выбран отдельной группой и перемещён на 10px. Протокол — docs/figma-check.md.

В режиме «По объектам» нераспознанные слова показываются в сообщении после сборки. Например, «книга и самолёт» создаёт книгу и сообщает, что самолёт не распознан в библиотеке. Неизвестные слова не заменяются выдуманной геометрией.

Заголовок управляет подбором; он не добавляется текстом в рисунок. Режим «Место под заголовок» резервирует свободную область для последующей вёрстки.

## Смысловой подбор

Используется pretrained модель **Xenova/paraphrase-multilingual-MiniLM-L12-v2**, quantized ONNX, через **Transformers.js 3.8.1**. Encoder кодирует фразу и части составного запроса. Двенадцать широких намерений задают одну-две смысловые опоры; остальные предметы ранжируются по отдельным описаниям десяти объектов и метаданным совместимости с контекстом. Обычный смысловой подбор возвращает 1–4 предмета, роли, смысловой центр heroId и причины выбора. Явно названные предметы обязательны во всех трактовках; если названо больше четырёх, они сохраняются. Чистое перечисление распознаётся по названиям и узким синонимам без семантического inference. Доступно десять разных предметов. Это семантический поиск по ограниченной библиотеке, не генеративная языковая модель и не универсальное понимание метафор.

Поддерживаемые области соответствуют исходным предметам: общение, сотрудничество, сбережения и бюджет, обучение, внимание, порядок в делах, планы, музыка, подарки, идеи, цифровые инструменты. Неподдерживаемые и слабые неоднозначные запросы могут быть отклонены; пользователь уточняет смысл или выбирает предметы явно. Отрицания, ирония и сложные переносные значения могут давать несовершенный результат. Модель никогда не добавляет предмет за пределами каталога и не генерирует изображений.

При слабом сходстве или близких трактовках студия сохраняет текущую сцену и предлагает выбрать тему. У уверенного результата тему можно раскрыть и сменить. Это даёт возможность исправить смысловой подбор до ручной доводки.

## Варианты и сохранение работы

Справа показаны три миниатюры реальных композиций. Для стандартного постера 1080 × 1440 в расположении «Собранно» пара телефон/пазлы использует вертикальную схему. В режиме «Место под заголовок» часть холста намеренно свободна; для произвольных размеров заполнение высоты не гарантируется. При автоматической сборке малых сцен перекрытие прямоугольных границ главных предметов консервативно ограничено; ручные правки остаются свободными. Выбор миниатюры или «Другой вариант» пересобирает расположение без повторного запроса к модели, сохраняя формат, S/L, палитру и режим места под заголовок. При автоматической перекомпоновке ручные позиции и повороты сбрасываются; их можно вернуть отменой.

Студия автоматически сохраняет текущий проект в localStorage этого браузера: предметы, их положения, повороты, слои, холст, палитру и ввод. Перезагрузка восстанавливает работу; история отмены относится к текущей сессии. Автосохранение на конкретном компьютере не заменяет переносимый файл: в меню **«Проект» → «Сохранить проект…»** можно скачать JSON и затем открыть его через **«Открыть проект…»**. JSON ссылается только на исходную библиотеку и не принимает произвольную SVG-геометрию. Размер проекта — до 1 МБ, до 50 экземпляров. Если хранилище браузера недоступно, интерфейс предлагает сохранить файл.

## Соответствие заданию

- 10 исходных предметов × два состояния × S/L = **40 реальных вариантов**, плюс три фона для каждого размера.
- Исходные SVG-пути не перерисовываются. Для всех предметов сцены используется **единый равномерный масштаб**, сохраняющий их относительные размеры.
- Два сценария: метафора/заголовок и явные названия компонентов.
- Автоматическая композиция с главным и фоновым планами, варианты расположения, разные форматы, свои размеры.
- Смысловой центр и правила взаимодействия пар телефон/пазлы, кошелёк/монета, книга/лампа; единый масштаб всей группы.
- Перемещение, поворот, дублирование, удаление, состояния, порядок слоёв, отмена/повтор.
- Три исходные схемы и загрузка палитры JSON с автоматической перекраской всей сцены.
- SVG сохраняет векторность; изображения-растр, внешние шрифты и новые иллюстративные объекты не добавляются.

## Палитра

JSON: `background` — три оттенка фона от светлого к тёмному; `objects` — три акцента и, необязательно, два нейтральных цвета (тёмный и белый). Формат — #RRGGBB. Пример: examples/palette-example.json. Фон не получает акценты объектов, исходный белый нейтральный декор сохраняется. Невалидный импорт не меняет сцену.

## Экспериментальный адаптер Figma

Папка figma-plugin содержит адаптер вставки SVG и экспорта выделения. Он **не проверен внутри Figma Desktop** и не является основной платформой сдачи. Проверенная платформа — самостоятельный браузерный сервис. Для разработки плагина нужен Figma Desktop и собственный дизайн-файл с правом редактирования. Может потребоваться заменить локальный id в manifest.json на ID, выданный Figma. Смысловой режим в iframe требует доступного локального сервера и соответствующего сетевого разрешения; текущий manifest не запрашивает внешнюю сеть.
