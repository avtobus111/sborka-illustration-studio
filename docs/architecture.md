# Архитектура

## Хранение и переиспользование SVG

source/library-S.svg и library-L.svg — исходные выгрузки Figma с ID и перекрывающимися слоями. scripts/extract_assets.py извлекает исходные группы, сохраняет path d и остальные атрибуты, переносит определения clipPath. Границы кубических кривых вычисляются по экстремумам; фон сохраняет исходную рамку. assets/catalog.json содержит 40 вариантов предметов и шесть фонов.

Координаты путей не переписываются. Для размещения применяются внешние translate, общий scale и поворот. Имена ID префиксуются отдельно для каждого экземпляра; внутренние ссылки обновляются.

## Смысловой выбор

src/semantic.mjs загружает quantized MiniLM через Transformers.js/ONNX Runtime CPU. Запрос и описания понятий кодируются в нормализованные векторы. Cosine similarity определяет широкое намерение и релевантность отдельных предметов. object-concepts.mjs содержит описания и совместимые контексты десяти предметов. intentAnchors задаёт 1–2 смысловые опоры; остальные ID выбираются динамически по запросу и его частям. Уверенное отдельное высказывание может добавить предмет другого контекста. Обычный выход — 1–4 ID, роли, heroId, причины и варианты трактовки. Общий parser component-names.mjs приоритетно распознаёт явно названные предметы, узкие синонимы и исключения; обязательные ID сохраняются во всех альтернативных трактовках, даже если их больше четырёх. Чистый список использует engine=catalog-names. Неизвестные положительные слова отображаются в явном режиме; они не заменяются предметами. Производные темы «монетизация» и «телефония» не являются названиями компонентов.

Описание тем ограничено наличием десяти видов предметов. Модель не создаёт изображения и не возвращает произвольные названия объектов. Слабые, неоднозначные и неподдерживаемые темы отклоняются. Число similarity является технической мерой сходства, а не вероятностью правильного ответа. Дополнительная проверка фрагментации токенов помогает отклонять бессмысленные низкоуверенные строки. Дополнительный предмет требует более сильного абсолютного сходства либо близости к лучшему объектному совпадению; слабый второй предмет не добавляется ради количества. Пороги не гарантируют универсальное понимание языка.

Опорные описания кодируются по одному, как запросы: это устраняет зависимость q8 activation scales от состава батча. Encoder и векторы тем хранятся в памяти процесса. Кэш результатов ограничен 100 запросами.

## Сервер и UI

scripts/serve.mjs слушает loopback 127.0.0.1, отдаёт HTML, GET /api/status и POST /api/select. Он не отправляет пользовательские запросы внешнему AI. JSON и длина запроса валидируются до inference. UI показывает загрузку/ошибку и сохраняет прежнюю сцену при неудаче. Счётчик версий не позволяет старому асинхронному ответу или ошибке перезаписать новую сборку.

После установки модель используется локально. scripts/setup-model.mjs скачивает только пять файлов из зафиксированной ревизии и проверяет SHA-256 из assets/model-manifest.json. models и node_modules не включены в Git. START.cmd устанавливает npm-зависимости при необходимости; launch.mjs проверяет модель, собирает отсутствующий HTML и запускает сервер с логом.

## Компоновка

createScene создаёт пары предмет/роль. Их перестановка не разрывает эту связь. Для 2–5 экземпляров используются позиции вокруг смыслового центра, три варианта и правила пар. Вертикальный стандартный постер учитывается отдельно для phone/puzzle. Главные предметы размещаются с лимитом .16 суммарных прямоугольных пересечений от последующих главных предметов; это консервативная оценка, не попиксельная маска. Фоновые предметы могут пересекаться с главными. Затем нормализуются общие границы и применяется единый scale. Для одного или более пяти предметов используется расчёт рядов. Формат и S/L пересчитывают раскладку. Пользователь может менять положение, поворот, роль и z-порядок вручную. При новой автоматической раскладке ручные позиции и повороты сбрасываются. До 50 экземпляров в сцене.

## Цвет и экспорт

Палитра разделена на фоновые оттенки и акценты/нейтральные цвета предметов. Перекраска заменяет fill/stroke по ролям, не меняя пути. Декоративный фон не получает объектные акценты. SVG содержит исходную геометрию, группы экземпляров, уникальные ID и clipPath рамки; внешних ресурсов и растра нет.

## Проверка и ограничения

70 автоматических проверок: геометрия и роли, три варианта, палитры, SVG и ссылки, JSON-проект, реальные смысловые запросы к модели, HTTP API и скачиваемые файлы. Дополнительно выполнена проверка браузера. Три итоговых примера генерируются реальной моделью через build.mjs; selections.json содержит запрос, состав и выбранную тему.

project.mjs сериализует только белый список полей и ID каталога; импорт проверяет версию, библиотеку, размеры, конечные трансформации, общий масштаб и число предметов. Служебные UID пересоздаются, произвольная SVG-геометрия не принимается. UI сохраняет проект в localStorage после изменения и поддерживает переносимый JSON. Режим components восстанавливает выбор из сохранённого ввода, даже если следующая сборка ещё не выполнена. История отмены между сессиями не сохраняется.

scene.backgroundStyle хранит индекс исходного декоративного фона отдельно от палитры; совпадение пользовательских цветов со встроенной схемой не меняет геометрию при восстановлении. Старые JSON без этого поля получают прежний индекс по palette.id.

scene.heroId задаёт смысловой центр. Для трёх пар действуют пространственные правила, затем минимальные координаты группы нормализуются и применяется общий scale. Старая версия JSON без heroId загружается с null; удаление последнего экземпляра смыслового центра очищает ссылку.

POST /api/export/svg и /api/export/project принимают JSON-проект в форме, валидируют через restoreProject и возвращают Content-Disposition attachment. SVG строится сервером только из каталога; произвольная входная разметка не принимается. Форма отправляется в служебный iframe, поэтому редактор остаётся открытым. В автономном file:// HTML и экспериментальном iframe Figma используется прежний Blob-export.

Смысловой ответ содержит до трёх alternatives и needsReview. При слабом сходстве/близком втором результате UI требует выбора темы и не заменяет текущую сцену. Любое ручное изменение инвалидирует ожидающий асинхронный подбор. Неподдерживаемая тема по-прежнему возвращает пустой набор.

Семантический охват ограничен библиотекой и темами, сложный контекст может быть понят неверно. Figma-адаптер экспериментальный и в настоящем хосте не проверен. Проверенная платформа сдачи — браузерный сервис.
