# Архитектура

## Хранение и переиспользование SVG

source/library-S.svg и library-L.svg — исходные выгрузки Figma с ID и перекрывающимися слоями. scripts/extract_assets.py извлекает исходные группы, сохраняет path d и остальные атрибуты, переносит определения clipPath. Границы кубических кривых вычисляются по экстремумам; фон сохраняет исходную рамку. assets/catalog.json содержит 40 вариантов предметов и шесть фонов.

Координаты путей не переписываются. Для размещения применяются внешние translate, общий scale и поворот. Имена ID префиксуются отдельно для каждого экземпляра; внутренние ссылки обновляются.

## Смысловой выбор

src/semantic.mjs загружает quantized MiniLM через Transformers.js/ONNX Runtime CPU. Запрос и описания понятий кодируются в нормализованные векторы. Вычисляется cosine similarity; побеждает подходящий смысловой профиль библиотеки. Профили в src/semantic-profiles.mjs задают связи смысла с существующими ID и ролями. Выбор не основан на совпадении префиксов запроса. Названия компонентов разбираются отдельно детерминированным parser в core.mjs.

Описание тем ограничено наличием десяти видов предметов. Модель не создаёт изображения и не возвращает произвольные названия объектов. Слабые, неоднозначные и неподдерживаемые темы отклоняются. Число similarity является технической мерой сходства, а не вероятностью правильного ответа. Дополнительная проверка фрагментации токенов помогает отклонять бессмысленные низкоуверенные строки. Пороги не гарантируют универсальное понимание языка.

Опорные описания кодируются по одному, как запросы: это устраняет зависимость q8 activation scales от состава батча. Encoder и векторы тем хранятся в памяти процесса. Кэш результатов ограничен 100 запросами.

## Сервер и UI

scripts/serve.mjs слушает loopback 127.0.0.1, отдаёт HTML, GET /api/status и POST /api/select. Он не отправляет пользовательские запросы внешнему AI. JSON и длина запроса валидируются до inference. UI показывает загрузку/ошибку и сохраняет прежнюю сцену при неудаче. Счётчик версий не позволяет старому асинхронному ответу или ошибке перезаписать новую сборку.

После установки модель используется локально. scripts/setup-model.mjs скачивает только пять файлов из зафиксированной ревизии и проверяет SHA-256 из assets/model-manifest.json. models и node_modules не включены в Git. START.cmd устанавливает npm-зависимости при необходимости; launch.mjs проверяет модель, собирает отсутствующий HTML и запускает сервер с логом.

## Компоновка

createScene создаёт пары предмет/роль. Их перестановка не разрывает эту связь. Малые сцены с фоновым предметом получают композицию с пересечением переднего и заднего плана; для остальных используется расчёт рядов с общим масштабом. Формат и S/L пересчитывают раскладку. Пользователь может менять положение, поворот, роль и z-порядок вручную. При новой автоматической раскладке ручные позиции и повороты сбрасываются. До 50 экземпляров в сцене.

## Цвет и экспорт

Палитра разделена на фоновые оттенки и акценты/нейтральные цвета предметов. Перекраска заменяет fill/stroke по ролям, не меняя пути. Декоративный фон не получает объектные акценты. SVG содержит исходную геометрию, группы экземпляров, уникальные ID и clipPath рамки; внешних ресурсов и растра нет.

## Проверка и ограничения

38 автоматических проверок: геометрия и роли, палитры, SVG и ссылки, реальные смысловые запросы к модели, HTTP API. Дополнительно выполнена ручная проверка браузера. Три итоговых примера генерируются реальной моделью через build.mjs; selections.json содержит запрос, результат и выбранную тему.

Сцены не сохраняются между перезагрузками — результат нужно скачать. Семантический охват ограничен библиотекой и темами, сложный контекст может быть понят неверно. Figma-адаптер экспериментальный и в настоящем хосте не проверен. Проверенная платформа сдачи — браузерный сервис.
